Can an AI agent fix a jammed 3D-printed hinge?

The task

What the agent gets

A printable box with a hinged lid as B-rep solids. While the lid opens, a rib under each lid knuckle swings into the top of the rear wall: it jams around 40–70°. The agent gets the bug report, every requirement with its threshold, the scoring formula and the protected zones with coordinates. Never the cause or the fix.

Tools (MCP)

  • Inspect: measure, section, edge/face queries
  • Edit: chamfer, fillet, offset_face, extrude_cut, cut_box, add_box, undo
  • Check: run_check_<id> (free), test_fit (2 free calls)
  • Budget: 150 tool calls, 1 hour

How it is scored

Any gate fails (broken solid, hinge or seal touched, protected zone cut, part rebuilt) → 0. Otherwise the opening sweep, printability and minimal change vs the best known fix (the agent is told the rule, never the volume).

S1 not met → 0.25 × progress
S1 met → 0.3 + 0.1×print + 0.6×minimal change

What separates the models

All of them find the clash. The gap is whether they keep working once a fix passes. The information was there in every run, so the remaining gap is a decision, not a missing fact.

Weaker models fall for the full-edge cut

Hydrogen tuned one full-edge chamfer on every attempt: 3.2× the best known volume, 0.400 on L2. It never tried a local relief.

Sonnet 5.5 stops at the first passing fix

Every rib fixed locally, gates and opening 9/9, but each trial called test_fit once and submitted the first fix that passed, with 120+ tool calls left. 0/9 tried to shrink a passing cut. On L3 all three used one relief size for three different ribs.

"I did not try to shrink the pockets further, so some of the minimal-change score may be left on the table."

Opus 5.5 is close, still below the reference on 3 of 9

It optimised after its first passing fix in 4/9 trials (undo, re-cut smaller, re-check). The L3 trial that sized each rib separately reached full points; it lost points where it skipped that step.

"Total now ~14.8 mm³ (was 23.3). Running the free checks."

Reward integrity

The verifier runs in a separate container with its own grader code, task copy and pristine parts. Doing nothing or stopping early scores 0; any working fix beats any broken one; a tailored fix beats a wasteful one. Exploit suite (python -m scenarios.hinge_lid.exploits --level L2,L3 --seeds 0):

shorten the ribs / cut the lid's hinge side0.0000.000G2, G3 keep-in

huge cut / cut through the seal band0.0000.000G3, G5 seal

Reproduce

From the repo (Docker + pip install harbor==0.26.0):

# reference run, agent x3, do-nothing, stop-early
harbor run -p harbor_tasks/judge -a oracle
harbor run -p harbor_tasks/judge -a opencode -m <provider/model> -k 3
harbor run -p harbor_tasks/judge -a nop
PYTHONPATH=. harbor run -p harbor_tasks/judge -a cadfix.harbor.agents:StopEarlyAgent
# open the 3D viewer of any run
scripts/view.sh jobs/<job>
